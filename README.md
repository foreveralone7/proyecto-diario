## 📏 Reglas del reto

1. Cada proyecto se termina en el día (2–3 horas). Si crece, se divide en partes.
2. Todo se publica en GitHub con un README que explique cómo correrlo.
3. Se rota entre frentes: frontend, backend, bases de datos, cloud, herramientas de terminal…
4. Se priorizan lenguajes nuevos: la meta es probar la mayor cantidad posible.
5. Se documentan los errores, no solo los aciertos.
